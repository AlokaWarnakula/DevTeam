## Important notes & decisions
- Treat `HANDOFF-TO-CODEX.md` as the first file to read when resuming. It accurately separates shipped work from the remaining backlog.
- Use `DEVTEAM-CHANGES-2026-08-09.md` as the shipped-change record and `DEVTEAM-COLLECTIVE-MIND-ROADMAP.md` as the consolidated backlog.
- Keep the longer Codex/Claude audits as evidence and design rationale; some of their original problems are already fixed.
- The current product is safer and more collaborative than the original 29-test version, but it is not a complete hive mind yet.
- Session-bound identity is working: the test suite proves one MCP session cannot act using another session's agent ID.
- The main heartbeat failure is fixed: silence changes a busy agent to `unresponsive` without transferring its write lease.
- Task rooms currently scope automatic claiming, inbox delivery, proposal visibility, unread counts, and proposal voter discovery.
- Room membership is still routing, not complete authorization. We proved that an agent joined to Task B can directly call `devteam_state` for Task A and post a message into Task A by supplying its ID.
- An `observer` can still claim the task's planner assignment. Observer permissions are recorded but not enforced by the scheduler.
- Implicit single-task membership is unstable. If a second active task is created, the original implicit member suddenly belongs to no room and stops receiving the first task's messages.
- One busy agent can still claim more than one assignment. The server needs a transactional guard and preferably a partial unique database index.
- Path-scoped leases need canonical filesystem validation. We proved that `src/hud` and `src/ocean/../hud` can both be claimed even though they resolve to the same directory.
- Write paths should be resolved against the canonical project root, reject traversal/ambiguous globs, normalize Windows case, and account for symlinks or junctions.
- The same-name/provider reconnect eviction is still active. A second Claude or Codex session can disconnect the first and release its work.
- Claim generations/tokens, resumable identity, proposal voter snapshots/quorum, reviewer-versus-author independence, shared blackboard memory, and verified file changes are still pending.
- Blocking or accepting a task still force-disconnects co-workers, which is increasingly risky now that non-overlapping writers can work in parallel.
- The dashboard does not yet show `unresponsive`, room membership, or write scopes, and it has no force-release control.
- The bundled skill, README, and guide still describe the older protocol. Update and resync installed skills only after the API stabilizes and the human approves deployment.
- Host/Origin guarding is an improvement, but `/api/config` still returns the MCP token and REST mutations do not have their own authenticated dashboard session.
- The repository is not a Git repository. That removes useful history and makes automatic diff/file-change verification harder.
- Preserve model diversity. The goal is shared facts, evidence, decisions, and memory—not forced agreement or automatic groupthink.
