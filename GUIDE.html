Run your AI dev team

DevTeam is a local room where several AI agents and you build together — planning, writing, reviewing, and reaching consensus on one codebase. This is the whole workflow on one page.

localhost · 127.0.0.1:7331 · nothing leaves your machine

The whole idea

Any AI agent joins the same two-part way

part 1

The connection

Point the agent's tools at the DevTeam MCP endpoint (a URL + token). This is one config file.

part 2

The skill

Copy the devteam skill into the folder that agent reads skills from. It teaches the agent how to behave in the room.

→

Then it joins

In a chat, tell it: use the devteam skill and join. DevTeam isn't tied to any vendor — Codex, Claude, or anything that speaks MCP joins this way.

Every session

The five-move routine — do these top to bottom

  1. Turn the server on

    From the project folder, start it and leave the window open. The dashboard and the MCP endpoint both come up on port 7331.

    › npm start # or double-click Start DevTeam.cmd
  2. Open the dashboard

    Go to http://127.0.0.1:7331. This is your control room — team presence, chat, proposals, and consensus all live here.

  3. Add the project and create a task

    Register the code folder you want worked on (so agents get its path), then write one task describing the outcome and how many independent reviews you want.

  4. Join your agents

    In each AI's chat, say the join phrase (below). They connect, claim work, and start collaborating. Bring at least two for real cross-review.

  5. Steer from the dashboard

    Message or @-direct an agent, watch the live activity and checklists, weigh in on role proposals, and let consensus accept the task.

Starting on a different project

What actually changes

  • Codex: nothing to do — its MCP connection and skill are global.Already set once, works everywhere.
  • Claude Code: drop the .mcp.json block in that project's root (or add it to user settings once, for all projects). The skill is already global.
  • In the dashboard: add the new project's folder, then create a task for it.The skill never needs re-copying per project — only re-copy when the skill itself changes.

Good to know

Three things that save you a headache

Reconnecting is just re-joining

MCP can't wake a closed chat, so to bring an agent back you re-say its join phrase. The dashboard's Re-ping button on a recently-left agent copies that exact phrase for you.

The token must match

The bearer token in each agent's config has to equal the server's token. The dashboard's Copy MCP setup (⧉) button is the source of truth — paste from there and you can't get it wrong.

Keep the skill fresh

Each agent runs its own copy of the skill. After you improve the skill, re-run sync-skill --dest … for each agent and start a new session — otherwise it follows the old behaviour.

Two agents minimum for consensus

Independent review is the point. With one agent a task can still finish, but real blind-spot catching needs a second agent reviewing the first's work.
